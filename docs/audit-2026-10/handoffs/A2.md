## For C1 / C2 / C3 (dates)

`src/lib/locale.ts` now has cached formatters (a `new Intl.DateTimeFormat` costs ~90 µs; list rows were paying it per row per render):

```ts
import { formatDate, formatDateTime, formatTime, dateFormatter } from '@/lib/locale'
formatDate('2026-10-07')              // '7 Oct'   (style 'day', the default)
formatDate(e.date, 'dayYear')         // '7 Oct 2026'
formatDate(ts, 'weekday')             // 'Tue 7 Oct'
formatDate(e.date, 'long')            // 'Tue 7 October 2026'
formatDate(ts, 'month')               // 'October 2026'   (GroupDetail month buckets)
formatDate(ts, 'monthShort')          // 'Oct'            (Insights axis)
formatDate(ts, { day: 'numeric', month: 'short', year: 'numeric' })  // any Intl options still work
formatDateTime(e.createdAt)           // '7 Oct 2026, 6:45 pm'  (replaces toLocaleString)
formatTime(ts)                        // '6:45 pm'
dateFormatter('day').format(d)        // the cached Intl.DateTimeFormat itself, for hot loops
```

Accepts 'YYYY-MM-DD' (local midnight), timestamps and Dates; returns '—' for anything unreadable. Please replace the `new Date(x + 'T00:00').toLocaleDateString(appLocale(), {...})` one-liners in your files with these (25 call sites: GroupDetail 294/400, Home 158, activity.ts 70/245 (A1), ExpenseDetail 76/151/226/234, Inbox 20, ImportGroup 340, StatementImport 43, Insights 205/211, Capture 140, ExpenseForm 927, DateField 28, Misc 89, ProfileCards 202–206, AutoCaptureSetup 168, Select 218 currency NumberFormat). Not required for correctness; it is the M3 perf item from 07-performance.md.

Also: `appLocale()` now returns `'en-IN-u-nu-latn'` (Western digits pinned, so ar-EG / fa-IR phones don't render ₹١٬٢٣٤). Any code comparing `appLocale()` to a bare tag would need `.startsWith('en-IN')`; A2 found none.
