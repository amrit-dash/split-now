# D1 done — USP features (phase 2)

All seven features from the plan, in order, wired for Firebase and demo mode, with unit tests for the pure parts. Flag-gated through D2's `useFlag()` / `flagOn()` (every flag defaults to on).

## 1. Remind → "Pay me" link + card
- New `src/lib/share-card.ts` (+ test, 9 cases): `settleLink()` builds `/groups/{gid}/settle?from={debtor}&to={me}&amount={minor}` (SettleUp already prefills from it), `reminderText()`, `cardSpec()` (pure wording incl. the UPI link for the QR), `renderShareCard()` (1080×1080 canvas PNG: brand gradient read from `--color-brand-600`/`--color-duo-600` with hex fallbacks, "Rahul → Priya", the amount, "Rahul owes Priya", the group, a UPI QR drawn from `src/lib/qr.ts` when the payee has a valid VPA and the group is INR, footer), `canShareFile()`, `shareReminder()` (files when `navigator.canShare({files})`, else text+url, else clipboard).
- New `src/components/RemindActions.tsx`: Remind (Share2 icon) + Nudge (BellRing) as two 44px labelled icon buttons; used on GroupDetail → Balances → "Who owes whom" rows where you are owed, and on Friends per group row where they owe you. The old Bell/`shareOrCopy` remind on GroupDetail is replaced.

## 2. Nudge push
- `functions/src/nudge.ts` (callable `nudge`), `functions/src/lib/nudge-core.ts` (+ test, 5 cases: amount clamping, copy, 1/day window), `nudgeNote()` in `functions/src/lib/notify-text.ts`, export in `functions/src/index.ts`. Server: caller must be a member; debtor must be a joined member (else `not_member`); amount = min(debtor's net owed, sender's net owed) with the app's figure clamped (never trusted); one per (sender, debtor, group) per day in `rateLimits/nudge_…` using `config/limits.nudgePerDay`; `sendToUser(debtorUid, ['reminders'], …)` honours the debtor's prefs (`no_push` when nothing is delivered); on success writes `settlement.nudged` to `groups/{gid}/activity` and `stats/nudge_{day}`; flag `nudges` → `off`.
- Client: `src/lib/nudge.ts` (+ test, 7 cases): `lastNudgeAt(feed, me, member)`, 24 h `nudgedRecently`, per-device memory (`rememberNudge` / `localNudgeAt`, demo mode has no server entry), result copy. `repo.nudge()` in both repos (demo: computes whether they owe you and answers `sent: true`, toast only). The button reads "already nudged today" (`aria-disabled`, title, toast on tap) from the group's activity feed or the local memory. `ActivityType` gains `'settlement.nudged'` (icon 🔔). Rules: `validEntry` now whitelists the 15 client-written types; a client cannot write `settlement.nudged`.

## 3. Duplicate warning
- New `src/lib/duplicates.ts` (+ test, 11 cases): `normaliseTokens`, `similarDescription` (containment or Jaccard ≥ 0.5; an empty description compares equal so amount + date carry it), `findDuplicate(expenses, { amount, cur, date, description, excludeId }, groupCurrency)` (same group list, |amount| equal — a foreign draft matches the stored `original` —, date within 1 day, not trashed, not the edited expense, repeating templates and their copies exempt, closest date then newest wins), `duplicateLine()` ("Looks like a duplicate of “Dinner” (₹1,200.00, yesterday)").
- `ExpenseEditor` shows the card (role=status, `dup-warning`) under the amount card with "Open it" and "It's a different expense, save anyway" (dismiss per duplicate id); `ExpenseForm` passes the group's live expenses. Capture prefill goes through the same editor, so it warns too; the one-tap "Split equally in <group>" on the capture prompt checks first and opens the form instead of saving when it finds one.

## 4. Merchant memory

## 5. Natural-language / voice quick add

- New `src/lib/speech.ts` (Web Speech API wrapper, `speechSupported`, `listenOnce`, plain error copy) and `src/components/QuickAdd.tsx`: labelled input, mic button only when supported (`aria-pressed` while listening; a final transcript opens the form), submit arrow, group picker (`Select`) on Home when there is more than one shared group. - Server: `functions/src/lib/gemini.ts` `TEXT_SCHEMA` (strict: description, amount, currency, date, payer, participants, category enum of the 12 ids), `textPrompt()` (member names in the system instruction, the note wrapped in `<note>` as untrusted data), `normaliseText()` (people kept to the listed names or "me"); `functions/src/ai.ts` `kind: 'text'` → `parseText()` through `withAi(ctx, 'images', …, 'text')` (same switch and allowance as bills; counted as `*_text`). ## Deliberately left out, and why
- **`/r/{code}` signed-out pay page** for debtors who haven't joined (10 §3 #1 option): an open question for the owner (it exposes the payee's UPI ID to anyone with the code); the card carries the UPI ID as text and a QR instead.
- **Duplicate check on the Inbox bulk "Add all"**: those captures are matched to a trip window and added in one go; a per-row warning there needs a different UI (a tick box per row already exists). The expense form and the one-tap add cover the two paths the plan named.
- **Merchant memory for SMS merchant prettifying** ("ZOMATO LTD" → "Zomato", 10 §3 #6): a different feature (display names), not categories.
- **A separate `text` AI feature flag / allowance**: text calls share the bill reader's switch, allowance and admin flag (`aiImages`) and are counted separately in stats (`*_text`); a dedicated switch would touch user prefs, config/ai and the settings screen (D2/C3 territory).
- **Quick add "split N ways" without names**: the hint is parsed (`ways`) but the form can't pick N anonymous people; the line opens with everyone selected and the user unticks. A toast would be noise.
- **Hinglish beyond a few words** ("aur", "kal", "aaj", "sab"): the grammar accepts them; speech recognition runs in `en-IN`.
- **Whose turn across groups / on Home**: the plan asked for GroupDetail + Insights; keeping it per group keeps it private and cheap.
- **Budget alert to the person who added the expense only once**: everyone gets it (including the adder), which is what a treasurer wants; the `expenses` preference turns it off per person.
- **FIREBASE_SETUP function table row for `nudge`**: the doc is D2/D3's in phase 2 (noted in D1.md).

## Decisions the owner should know
- **Remind now shares a link into the friend's prefilled Settle up screen** (plus a PNG card with a UPI QR where the share sheet takes files), not the group page. The text reads "Hey Rahul, friendly nudge: you owe Priya ₹1,240.00 for “Goa trip”. UPI: priya@okaxis. Pay in one tap:" followed by the link.
- **Nudge is server-enforced at one per (you, them, group) per day** (admin-tunable via `config/limits.nudgePerDay`) and respects the debtor's "reminders" push preference: a debtor who turned reminders off gets no nudge, and you are told to share a reminder instead. The amount in the push is what they owe in the group capped at what you are owed; the app's shown figure (the simplified debt) is clamped to that. The activity feed shows "Priya nudged Rahul to settle up (₹1,240)" to the whole group.
- **Rules now whitelist activity types**: the 15 kinds the app writes. Any future client-written type must be added to `firestore.rules` `validEntry` (and the test) or its write fails.
- **Merchant memory wins over the group's own history** for a description, which wins over the keyword guess. It learns only from categories you picked by hand that differ from the suggestion; it never learns "Other" by default.
- **Duplicate warning is advisory**: it never blocks a save; "save anyway" dismisses it for that match. Repeating expenses are exempt.
- **Quick add never saves**: it opens the form filled in. The AI read runs only when the local parse is unsure and the device's AI reading switch is on; the note is sent as text with the group's member names (no uids), and the server returns names which the app resolves.
- **Budget pushes go to members with expense notifications on**, once per threshold per budget figure; raising or lowering the budget re-arms both thresholds.
- **"Whose turn"** is visible only to the viewer, based on the last 90 days of the group; it says nothing when nobody stands out.
