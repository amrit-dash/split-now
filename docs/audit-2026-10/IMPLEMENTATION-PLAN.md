## Global rules for every track
1. Edit ONLY the files your track owns (list below). If you need a change elsewhere, write a precise request (file, exact change, why) to `docs/audit-2026-10/handoffs/<track>.md` and keep going. Never edit package.json / package-lock.json (track E only) and never run `npm install`.
2. Do NOT commit, stash, checkout, reset or otherwise touch git state. The lead commits. Do not run `vite build` (track A2 only) and do not start the Firebase emulators (track B only; E's rules tests are run by the lead). `npx tsc -b` and `npx vitest run <paths>` are fine any time.
3. Other agents are editing other files concurrently: always re-read a file right before editing it, and prefer small targeted edits over whole-file rewrites of files you share with nobody — but whole-file rewrites of files you OWN are fine.
4. Keep the existing code style: no semicolons, single quotes, 2-space indent, long lines OK, `@/` alias, pure logic in `src/lib` with vitest tests next to it (add tests for every pure function you add or fix). Keep comments that explain *why*; write new ones in the same voice.
5. Mobile-first (360–430px). Every new control: ≥44px tap target or ≥24px with spacing, labelled (`<label htmlFor>` or aria-label), keyboard operable, no colour-only state (aria-pressed/aria-checked/role=radio + text or icon), `inputMode` on numeric fields, `type="button"` inside forms.
6. Copy: plain English, no jargon, no exclamation marks, terminology glossary: "Add expense" (not create), "Record a payment"/"Settle up", "Split by items" (the itemised split), "Live table" (the QR shared bill), "Captured payment" (an SMS/share capture), "Capture key" (the token), "Scan" (OCR/AI reading of a photo), "Needs your OK" (approval), "Flagged" (dispute).
7. Finish = `npx tsc -b` exit 0 and `npx vitest run` green for the whole repo (not just your files) + your own summary in `docs/audit-2026-10/handoffs/<track>-done.md`: what changed (file list), what you verified, what you deliberately left out and why, and any decision the owner should know. Return a ≤25-line summary as your final message.
8. The reports in `docs/audit-2026-10/reports/` are your detailed specs; read the ones named in your track in full before starting. They are findings by auditors: verify each claim against current code (the foundation commit may have changed a line number) and skip anything already fixed. You MAY spawn sub-agents for sub-areas; give them the same ownership list and rules.
