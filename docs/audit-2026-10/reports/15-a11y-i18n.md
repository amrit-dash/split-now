# 15 — Accessibility, internationalisation and input handling

Static review of every file in `src/components` (28) and `src/pages` (22), plus `src/main.tsx`, `src/App.tsx`, `src/index.css`, `index.html`, `src/lib/locale.ts`, `src/lib/money.ts` and the date helpers they call. No browser was run; claims about colour were computed with a WCAG 2.x contrast script (oklch → sRGB, Tailwind v4 palette values taken from `node_modules/tailwindcss/theme.css`, alpha composited), and the timezone claims were reproduced with `TZ=… node -e`. Counts below come from `rg` over `src/components`, `src/pages`, `src/App.tsx`, `src/hooks` unless stated.

**Verdict.** The component layer is better than most hand-rolled React UIs: `Select` is a proper keyboard combobox, `Collapsible` uses `inert`, every icon-only button has an `aria-label`, every `<img>` has `alt`, money goes through `formatMoney`/Intl everywhere (99 uses, zero `$`/`toFixed` bypasses, zero hard-coded `'en-IN'` in UI code), and amount fields use `inputMode="decimal"`. The failures are systemic rather than scattered: (1) the bottom `Sheet` is not a real modal (no focus trap, no inert background, no accessible name when untitled); (2) the colour system fails AA in both themes — `text-slate-400` on white is 2.63:1, placeholders 2.40:1, `.pos` green is 3.67:1, and in dark mode the 197 `text-slate-500` lines without a `dark:` variant sit at 3.91:1; (3) `<html lang>` is overwritten with the *formatting* locale, so a Japanese or Bengali phone gets `lang="ja-JP"`/`"bn-BD"` on English copy and Bengali digits in amounts; (4) a real timezone bug: the Insights monthly series is keyed by `toISOString()`, so in India (and every UTC+ zone) spending is attributed to the following month and the current month is dropped; (5) the `prefers-reduced-motion` rule lacks `animation-iteration-count: 1`, so the 20+ infinite animations flicker instead of stopping; (6) selection state (chips, segmented controls, split types, method pickers) is colour-only with no `aria-pressed`. None of these block use, but together they put the app below WCAG 2.2 AA on contrast (1.4.3, 1.4.11), name/role/value (4.1.2), focus visible (2.4.7), language of page (3.1.1) and page titled (2.4.2).

#### H1. Insights "Spending over time" buckets months by UTC — wrong for India and every UTC+ zone  [Certain — reproduced]
`src/pages/Insights.tsx:201-207`
```ts
const start = new Date(first.slice(0, 7) + '-01T00:00')          // local midnight on the 1st
for (let d = new Date(start); d <= now; d.setMonth(d.getMonth() + 1)) {
  const k = d.toISOString().slice(0, 7)                            // UTC → previous month in UTC+
  series.set(k, { label: d.toLocaleDateString(appLocale(), { month: 'short' }), value: 0 })
}
for (const r of rows) { const s = series.get(r.e.date.slice(0, 7)); if (s) s.value += r.v }
```
`TZ=Asia/Kolkata node -e "new Date('2026-10-01T00:00').toISOString().slice(0,7)"` → `2026-09`, while the label for the same `d` is `Oct`. So the bucket labelled "Oct" has key `2026-09`; October expenses (`e.date.slice(0,7) === '2026-10'`) land in the bucket labelled "Nov", and because the loop stops at `d <= now`, there is no `2026-10` key at all → **the current month's spending disappears from the chart and every other month is shifted one label to the right.** In New York the key is `2026-10` and the chart is right, i.e. the bug hits exactly the primary market. Why it matters: the headline chart on Insights is wrong for Indian users; it is the kind of thing that erodes trust in the numbers.
**Fix:** derive the key from local date parts, never from `toISOString()`:
```ts
const key = (d: Date) => `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}`
for (let d = new Date(start); d <= now; d.setMonth(d.getMonth() + 1)) series.set(key(d), { label: …, value: 0 })
```
Same file, same class of bug (lower impact): `:176` `cutoff = new Date(now - days*86400000).toISOString().slice(0,10)` and `:201` `now.toISOString().slice(0,10)` use the UTC calendar date; between 00:00 and 05:30 IST the cutoff is a day early. Use `todayISO()`/`addDaysISO()` from `src/lib/id.ts` / `src/lib/recents.ts` (both already local-safe). Add a unit test for `compute()` that runs under `TZ=Asia/Kolkata` (vitest honours `process.env.TZ` if set in `vitest.config.ts` → `test.env`).

#### H2. `<html lang>` is set to the *formatting* locale, and non-Latin numbering systems leak into an English UI  [Certain — reproduced]
`src/main.tsx:13-14`
```ts
const locale = initLocale()
try { document.documentElement.lang = locale.locale } catch {}
```
`index.html:2` correctly declares `lang="en"`, but `main.tsx` overwrites it with whatever `localeFor()` (`src/lib/locale.ts:76-80`) returns: `ja-JP` for a Japanese phone, `de-DE`, `fr-FR`, `bn-BD`, `ar-SA`, etc. Every string in the app is English. Screen readers switch synthesiser voice/language based on `lang` (WCAG 3.1.1 Language of Page): a Japanese-locale VoiceOver user hears English copy read with Japanese phonetics; browsers also pick hyphenation dictionaries, quotation glyphs and CJK fallback fonts from `lang`. Separately, `formatMoney`/`formatDate` pass that locale to `Intl`, whose default numbering system is not Latin for several locales the app explicitly supports via `REGION_CURRENCY` (`locale.ts:19-24` lists `BD`, `SA`, `QA`, `AE`, `PK`): `new Intl.NumberFormat('bn-BD',{style:'currency',currency:'BDT'}).format(1234.56)` → `১,২৩৪.৫৬৳` (verified). A Bangladeshi user with a Bengali-language phone sees Bengali digits in amounts and dates, Inter (which has no Bengali digits) falls back per glyph, and `parseMoney` (`money.ts:63`) strips those digits as non-`\d` when the user re-types a value they were shown.
**Fix (two lines + one):**
1. Never derive `lang` from the formatting locale. Delete `main.tsx:14` (keep `index.html` `lang="en"`), or if you want region-flavoured English, set `document.documentElement.lang = \`en-${locale.region}\`` only — the UI language is English until strings are translated.
2. Force Latin digits for formatting while keeping regional conventions: in `locale.ts:resolveLocale` after computing `locale`, append the Unicode extension: `locale = new Intl.Locale(locale, { numberingSystem: 'latn' }).toString()` (gives e.g. `bn-BD-u-nu-latn`), or pass `numberingSystem: 'latn'` in the `Intl.NumberFormat`/`toLocaleDateString` options in `money.ts:39,41,51`, `locale.ts:127` and the 18 `toLocaleDateString(appLocale(), …)` call sites (simplest: route them all through `formatDate`).
3. Add a `locale.test.ts` case: `resolveLocale('bn-BD','Asia/Dhaka')` formats `1234.56` with ASCII digits.

#### H3. `Sheet` is not a modal dialog: no focus trap, no initial/return focus, background not inert, unnamed when untitled, iOS scroll lock ineffective  [Certain]
`src/components/Sheet.tsx:4-27` (17 call sites).
- Nothing moves focus into the sheet on open, nothing returns it to the trigger on close. A keyboard/switch user who taps the FAB (`Layout.tsx:39-47`) stays focused on a button that is now behind a backdrop; Tab continues through the page underneath (the tab bar, the whole form).
- `aria-modal` is set but the rest of the document is neither `inert` nor `aria-hidden`, so VoiceOver's rotor and swipe navigation still reach the background. (`Collapsible.tsx:56` already uses `inert`, so React 19's support is proven in this codebase.)
- `role="dialog"` has no accessible name: `title` is optional and when present the `<h2>` is not linked via `aria-labelledby`. All 17 current callers pass a title, but the API allows an unnamed dialog.
- The backdrop is `<div onClick>` (`:15`), the only `onClick` on a non-interactive element in the codebase — acceptable because `Escape` and the Close button exist, but mark it `aria-hidden`.
- `document.body.style.overflow = 'hidden'` (`:9`) does not stop background scrolling in iOS Safari; the inner `overflow-y-auto` panel (`:16`) lacks `overscroll-contain`, so reaching its end scroll-chains the page.
- Not portalled: it renders inside the page tree (works today because `z-50` beats the sticky header `z-30` and nav `z-40`, but `StatementImport`/`SplitBill`/`Table` render their own `fixed … z-40` bottom bars which the sheet must out-stack by luck).
**Fix:** replace the hand-rolled wrapper with the native `<dialog>` (`showModal()` gives focus trap, Escape, top layer, `::backdrop`, and makes the rest of the page inert for free), or keep the markup and add: `createPortal(…, document.body)`; `useEffect` that saves `document.activeElement`, focuses the first focusable (or the panel with `tabIndex={-1}`), sets `inert` on `#root`'s other children, and on close restores `inert` and focus; `aria-labelledby={titleId}` with `useId()` and require `title` or `aria-label` in the prop type; `overscroll-contain` on the panel; for iOS use the `position: fixed; top: -scrollY; width: 100%` body technique or `touch-action: none` on the backdrop. The same gaps apply to `CreateSheet`, `PhotoSheet`, `RecentlyDeleted`, `TableFinish`, `EditBillSheet`, `AddPersonSheet` since they all compose `Sheet`.

#### H5. `prefers-reduced-motion` rule makes infinite animations flicker instead of stopping  [Likely]
`src/index.css:145-147`
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```
Without `animation-iteration-count: 1 !important`, an `infinite` animation keeps looping every 0.01 ms; each painted frame samples an arbitrary phase, so `animate-spin` (13 uses — every busy button, `Spinner`), `animate-pulse` (`Misc.tsx:70` live dot), the seven Aurora blob/bubble/conic animations (`index.css:173-179`, `Aurora.tsx`, i.e. the Home hero card and the FAB), `animate-float` (`Home.tsx:83`) and the OCR `indeterminate` bar (`SplitBill.tsx:141`, `Scan.tsx:118`) jitter/flicker. This is the well-known hole in this reset pattern; the `Aurora.tsx` comment ("Stops under prefers-reduced-motion") is therefore wrong — for vestibular users it gets worse, not better. Note also that `motion-reduce:transition-none` is applied in only 5 places, all redundant with the global rule.
**Fix:**
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; transition-duration: 0.01ms !important; scroll-behavior: auto !important; }
  .animate-spin { animation: none !important; }   /* keep spinners static but visible */
}
```
and in `Aurora.tsx` render a static gradient (no animated children) when `matchMedia('(prefers-reduced-motion: reduce)').matches`, since a static blurred blob is the intended fallback.

#### H6. No visible focus indicator on the main amount/description inputs, and no app-wide `:focus-visible` style  [Certain]

For `renderTrigger` add `focus-visible:ring-2 focus-visible:ring-brand-500` to `triggerClassName` default.
